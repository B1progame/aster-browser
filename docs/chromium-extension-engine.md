# Aster Chromium extension engine investigation

## Finding

Chrome extensions require a Chromium extension runtime. Renaming a `.crx` to `.xpi` or translating the archive cannot reproduce arbitrary APIs, background service workers, permissions, native messaging, or browser UI in GeckoView. There is no universal converter that provides full desktop parity on Android.

Aster now has an experimental real Chromium route based on the Afterbird patch set. Afterbird re-enables desktop Android extension support in Chromium and patches Android-specific extension issues. This is a browser-shell replacement, not an embeddable engine library. Afterbird reports Chrome Web Store installation and selected MV2/MV3 extensions (uBlock Origin, Dark Reader, Stylus, Violentmonkey, SponsorBlock, Bitwarden, and uBO Lite). These are project-reported examples, not all individually verified by Aster.

Chromium's own build-flag documentation describes desktop Android extensions as experimental and still in development. The extension API surface also includes platform-limited APIs (for example, ChromeOS-only APIs) and native messaging depends on a host program installed for the platform, so source-compatible extension files do not imply identical desktop behavior on Android. See [Chromium's extension build flags](https://chromium.googlesource.com/chromium/src/+/main/extensions/docs/buildflags.md), the [Chrome Extensions API reference](https://developer.chrome.com/docs/extensions/reference/api), and [native messaging requirements](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).

The current Chromium source tree's `extensions/buildflags/buildflags.gni` (checked 2026-10-15) still labels `enable_desktop_android_extensions` experimental and says the scope is expanding incrementally. Chromium's Android extension porting changes explicitly defer policy integration and MV2 in upstream desktop Android; Aster's pinned Chromium 151 Afterbird patch series re-enables selected MV2 paths. This improves coverage for older store extensions, but it cannot supply desktop-only APIs or native host programs. The current upstream flag is described in [Chromium's buildflags source](https://chromium.googlesource.com/chromium/src/+/HEAD/extensions/buildflags/buildflags.gni); see also this [Chromium extension-porting change](https://chromium.googlesource.com/chromium/src/+/3c17b5e18899f3e9bbcd299ba9e2ffbda390833d%5E%21/).

## Constraints and unfinished work

- This is not support for every Chrome extension. Native messaging, missing/desktop-only APIs, permissions and UI that assume a PC, and browser policies can still prevent an extension from working. A universal converter cannot solve those runtime incompatibilities.
- Extension coverage remains limited: the localized MV3 smoke test, DNR fixture, and uBlock Origin Lite install/filter test verify selected paths only. They do not establish broad service-worker/API compatibility or universal extension support.
- Aster visual changes cover the new-tab page, extension shortcut, dark-first browser theme, native tab grid, and a phone-width extension manager with an Aster mint/charcoal palette. Extension-management behavior and most menus, settings, and browser controls remain Chromium's native UI; the full app-wide redesign and custom motion system are still incomplete. The Chromium extension sheet now provides site-level extension access and per-extension enable controls on phones; a separate Aster-native shield/settings system and Aster-specific immersive VR-controller UI are not implemented. Patch `0018` bundles removable uBlock Origin; its runtime behavior is verified only for the prior x86_64 Chrome Web Store uBlock Origin Lite test, not for the bundled extension on ARM64.
- ARM64 build validation is incomplete: the APK builds and installs, but the x86_64 emulator's native bridge caused renderer failures and an ANR. A native ARM64 Android phone/Quest run is required before claiming runtime compatibility.
- Existing GeckoView profile data cannot be migrated into Chromium's different profile format. The Chromium test app uses a separate package ID to preserve the existing Aster install.
